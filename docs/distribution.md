# Distribution, Suggestions, and Calibration Data Contracts

This document specifies the JSON schemas and exact metric definitions produced by `lerobot-check` and consumed by `xense-lerobot-viewer`.

Synthetic reference fixtures generated by `lerobot-check` live in [tests/fixtures/distribution.example.json](../tests/fixtures/distribution.example.json) and [tests/fixtures/suggestions.example.json](../tests/fixtures/suggestions.example.json).

## Shared File Layout

All files live under `<lerobot_root>/.xense-viewer/`, where `<lerobot_root>` is the grandparent of the dataset directory (for example `~/.cache/huggingface/lerobot`) and `<org>__<name>` replaces `/` with `__` in `repo_id`:

| Path | Writer | Purpose |
| --- | --- | --- |
| `subtasks/<org>__<name>.task_spec.yaml` | human / agent | Ordered subtasks, optional per-subtask `cameras` and `arms`, object specs, coverage bins |
| `subtasks/<org>__<name>@<revision>.csv` | agent / viewer | Per-episode subtask boundaries and `grasp` frames |
| `distribution/<org>__<name>@<revision>.json` | `lerobot-check distribution` | Frame shares, object poses & coverage grids, per-subtask trajectories & metrics |
| `object-poses/<org>__<name>@<revision>.json` | `lerobot-check object-poses` | Frame-0 head-camera object outlines, derived poses, and per-episode statuses |
| `targets/<org>__<name>.json` | viewer | Target placement polygon in head-camera pixel coordinates |
| `suggestions/<org>__<name>@<revision>.json` | `lerobot-check suggest` | Collection placements and 3-tier evaluation test points |
| `calib/<org>__<name>.intrinsics.json` | user / camera | Head-camera intrinsics and distortion coefficients |
| `calib/<org>__<name>.frames.json` | `lerobot-check calib-frames` | FPS-selected frames with TCP poses for manual point picking |
| `calib/<org>__<name>.points.json` | viewer | Clicked fingertip midpoint pixels (`[u, v]`) or `skipped: true` |
| `calib/<org>__<name>.head.json` | `lerobot-check calibrate` | Per-arm `T_cam_base`, `tool_offset`, RMS & LOO errors, residuals |

## `distribution.json` (Schema Version 1)

Generated by `lerobot-check distribution`. Units are explicit in field names (`_m` for meters, `_deg` for degrees, `_cm` for centimeters).

### Top-Level Fields

| Field | Type | Description |
| --- | --- | --- |
| `version` | `int` | Always `1`. |
| `provenance` | `object` | Dataset, annotation path, annotator counts, and episode inclusion metadata. |
| `coverage_config` | `object` | `{xy_bin_m, yaw_bin_deg, sparse_threshold}` copied from the task spec. |
| `trajectory_samples` | `int` | Number of progress samples $K$ per trajectory (default `50`). |
| `frame_shares` | `object` | Per-subtask frame counts and shares over included annotated episodes. |
| `episodes` | `list[object]` | Per-annotated-episode subtask rows so the viewer can recompute frame shares and provenance for any subset. |
| `objects` | `list[object]` | Per-object initial poses, skipped events, median event-frame $z$, and XY $\times$ yaw coverage grid. |
| `subtasks` | `list[object]` | Per-subtask participating arms, per-episode start/end poses and progress trajectories, and summary metrics. |

### `provenance`

- `repo_id` (`str`), `revision` (`str`), `task_name` (`str`)
- `annotations_path` (`str | null`), `task_spec_path` (`str | null`)
- `position_point` (`"tool_point" | "tcp"`): `"tool_point"` when `head.json` calibration was applied so positions are computed at `p_tcp + R_tcp @ tool_offset` for each calibrated arm; `"tcp"` when no calibration was used.
- `calib_path` (`str | null`): resolved `head.json` path used, or `null` when uncalibrated.
- `calib_mtime` (`str | null`): UTC ISO-8601 modification timestamp of `head.json`, or `null`.
- `calibrated_arms` (`list[str]`): sorted arm names whose `tool_offset` was applied (empty when uncalibrated).
- `fps` (`float`)
- `annotator_counts`: `{"agent": int, "human": int, "converted": int, "total": int}` (counted over included rows)
- `dataset_total_episodes` (`int`): total episodes in dataset metadata
- `episode_filter` (`list[int] | null`): sorted episode indices when `--episodes` was supplied, otherwise `null`
- `annotated_episodes` (`list[int]`): sorted annotated episodes included in this file
- `skipped_episodes` (`list[int]`): sorted episodes in the considered set (full dataset or `episode_filter`) absent from the annotation table
- `object_poses_sha256` (`str`, optional): SHA-256 hex digest of the `object-poses` sidecar JSON file. Present only when at least one object entry carries `object_layer`; omitted otherwise.

### `frame_shares`

- `total_frames` (`int`): sum of `end - start` over all included annotation rows.
- `subtasks` (`list[object]` in task-spec order):
  - `subtask` (`str`): subtask name
  - `episodes` (`int`): number of distinct annotated episodes containing this subtask
  - `frames` (`int`): total frames across those episodes
  - `share` (`float`): `frames / total_frames` in `[0.0, 1.0]` (`0.0` when `total_frames == 0`)

### `episodes`

Sorted by `episode_index`. Each entry:
- `episode_index` (`int`), `length` (`int`)
- `subtasks`: ordered list of `{"subtask": str, "start": int, "end": int, "frames": int, "grasp": int | null, "success": bool, "annotator": str}`

### `objects`

In `task_spec.objects` order. Existing fields (`median_z_m`, `poses`, `skipped`, `coverage`) form the **end-effector layer** (TCP/tool-point pose at each object's grasp or release event frame). When an `object-poses` sidecar is present, objects configured with `layout_box` in the task spec also carry an **object layer** (`object_layer`) measured directly from episode frame 0 in the head camera.

Each entry:
- `name` (`str`), `subtask` (`str`), `event` (`"grasp" | "release"`), `arm` (`"left" | "right"`), `yaw_symmetry_deg` (`float`)
- `median_z_m` (`float | null`): median of `z_m` across `poses` (`null` when `poses` is empty; reflects calibrated tool-point `z` when `position_point == "tool_point"`)
- `poses`: list of `{"episode_index": int, "frame": int, "arm": str, "x_m": float, "y_m": float, "z_m": float, "raw_yaw_deg": float, "folded_yaw_deg": float, "rot6d": [r1, r2, r3, r4, r5, r6]}`
  - Event frame is `row.grasp` for `event == "grasp"` and `row.end - 1` for `event == "release"`.
  - `(x_m, y_m, z_m)` is `p_tcp + R_tcp @ tool_offset` when calibrated, or raw `p_tcp` when uncalibrated.
  - `raw_yaw_deg` is ZYX yaw in `(-180, 180]` degrees from `atan2(R[1, 0], R[0, 0])` (fallback `atan2(-R[0, 1], R[1, 1])` when `hypot(R[0, 0], R[1, 0]) <= 1e-6`).
  - `folded_yaw_deg = raw_yaw_deg mod yaw_symmetry_deg` in `[0, yaw_symmetry_deg)`.
  - `rot6d` stores the 6D TCP orientation `[r1..r6]` at the event frame (first two columns of `R_tcp`) so the viewer can render gripper axes if needed.
- `skipped`: list of `{"episode_index": int, "reason": str}` for episodes where the object's subtask or `grasp` frame is absent.
- `coverage`:
  - `sample_count` (`int`), `xy_bin_m` (`float`), `yaw_bin_deg` (`float`), `sparse_threshold` (`int`), `num_yaw_bins` (`int`)
  - `ix_range` (`[int, int] | null`), `iy_range` (`[int, int] | null`)
  - `bins`: all cells across `[ix_min..ix_max] x [iy_min..iy_max] x [0..num_yaw_bins-1]`, each:
    `{"ix": int, "iy": int, "yaw_bin": int, "x_min_m": float, "x_max_m": float, "y_min_m": float, "y_max_m": float, "yaw_min_deg": float, "yaw_max_deg": float, "count": int}`
  - Cell indexing: `ix = floor(x_m / xy_bin_m)`, `iy = floor(y_m / xy_bin_m)`, `num_yaw_bins = max(1, ceil(yaw_symmetry_deg / yaw_bin_deg - 1e-9))`, `yaw_bin = min(floor(folded_yaw_deg / yaw_bin_deg), num_yaw_bins - 1)`.
- `object_layer` (`object`, optional; absent when no `object-poses` sidecar was used or the object has no `layout_box`):
  - `source` (`"head_mask"`), `frame` (`0`), `arm` (`str`), `plane_z_m` (`float | null`), `yaw_period_deg` (`float`, equals `min(yaw_symmetry_deg, 180.0)`; the rectangle long axis is only defined modulo 180°, so objects with a layout box must use a `yaw_symmetry_deg` that is `>= 180` or divides 180, otherwise `object-poses` and `distribution` reject them)
  - `poses`: list of `{"episode_index": int, "frame": 0, "arm": str, "x_m": float, "y_m": float, "z_m": float, "raw_yaw_deg": float, "folded_yaw_deg": float, "length_m": float, "width_m": float}`
    - `(x_m, y_m, z_m)` is the polygon centroid of the frame-0 mask outline back-projected onto `z = plane_z_m` in `arm`'s base frame.
    - `raw_yaw_deg` is the long-axis direction of the minimum-area bounding rectangle of the back-projected outline in `[0, 180)` degrees; `folded_yaw_deg = raw_yaw_deg mod yaw_period_deg` in `[0, yaw_period_deg)`.
    - `length_m` and `width_m` are the rectangle side lengths in meters (`length_m >= width_m`).
  - `skipped`: list of `{"episode_index": int, "reason": str}` for episodes rejected due to empty/degenerate mask, mask touching `layout_box` border, rectangle size far from the object's cross-episode median, or missing arm calibration. Episodes in the considered set that the sidecar never measured (for example `object-poses --episodes` ran on a subset) are listed with reason `"episode not in object-poses sidecar"`.
  - `coverage`: identical schema and binning function as the end-effector `coverage`, computed over `object_layer.poses` using `yaw_period_deg` and `coverage_config`.

### Object-Poses Sidecar (`object-poses/<org>__<name>@<revision>.json`, Schema Version 1)

Generated by `lerobot-check object-poses` for objects carrying `layout_box: [x0, y0, x1, y1]` (native head-camera pixels at frame 0, `0 <= x0 < x1`, `0 <= y0 < y1`) and optional `object_plane_z_m` (default: end-effector `median_z_m`) in `task_spec.yaml`.

- Top-level keys: `version: 1`, `repo_id`, `revision`, `camera`, `image_size: [W, H]`, `frame: 0`, `calibration_sha256`, `model`, `model_revision`, and `objects`.
- `objects.<name>`: `arm`, `layout_box`, `plane_z_m`, `yaw_period_deg`, and `episodes`, where each episode record stores `episode_index`, `frame`, `status` (`"ok"` or a skip reason), `outline` (exterior polygon `[[u, v], ...]` in native head pixels, or `null`), and the derived pose fields (`x_m`, `y_m`, `z_m`, `raw_yaw_deg`, `folded_yaw_deg`, `length_m`, `width_m`, all `null` when `status != "ok"`). Records segmented with an `object-poses --prompt-box EP:OBJECT=x0,y0,x1,y1` override also carry `prompt_box: [x0, y0, x1, y1]`, the box that replaced the object's `layout_box` for that episode (segmentation prompt and border check); records without it used `layout_box`.
- Passing `--sheet DIR` writes paginated JPEG review sheets (`object_poses_p01.jpg`, ...) with one frame-0 cell per episode, drawing each object's `layout_box`, mask outline, name label, and skipped-object reasons.
- `lerobot-check distribution` automatically loads the sidecar from the default path (or `--object-poses PATH`) and rejects any sidecar whose `repo_id`, `revision`, or `calibration_sha256` does not match the dataset and `head.json`, or whose object records are malformed (non-numeric pose fields on an `ok` record, missing `arm`/`status`/`episodes`, duplicate episodes, or an `arm` that differs from the task spec). Without a sidecar, `distribution.json` output is byte-for-byte unchanged.

### `subtasks`

In `task_spec.subtasks` order. Each entry:
- `name` (`str`), `prompt` (`str`), `participating_arms` (`list[str]`)
  - `participating_arms` uses `subtask.arms` if explicitly configured in the task spec, otherwise the unique arms of `task_spec.objects` belonging to that subtask.
- `arms`: mapping `arm_name -> {"metrics": ..., "episodes": [...]}`
  - `episodes` (sorted by `episode_index`):
    - `episode_index` (`int`)
    - `start_frame` (`int`): frame used for `start_pose` — equals `row.grasp` when `grasp` is annotated, otherwise falls back to `row.start`
    - `start_source` (`"grasp" | "start"`): indicates whether `start_pose` came from `row.grasp` or fell back to `row.start`
    - `end_frame` (`int | null`): equals `row.end - 1` for non-final subtasks; `null` for the last subtask in task-spec order (which runs to episode end including final retraction)
    - `start_pose`: `{"x_m": float, "y_m": float, "z_m": float, "yaw_deg": float, "rot6d": [r1..r6]}` at `start_frame`
    - `end_pose`: `{"x_m": float, "y_m": float, "z_m": float, "yaw_deg": float, "rot6d": [r1..r6]}` at `end_frame`, or `null` for the last subtask in task-spec order (excluded from end coverage and end yaw histograms)
    - `trajectory`: `K` progress-resampled points `{"progress": float, "x_m": float, "y_m": float, "z_m": float, "yaw_deg": float}` (no `rot6d` per trajectory sample) covering the full subtask interval `[row.start, row.end)` at `progress_i = i / (K - 1)` for `i = 0 .. K-1`.
      - Positions `(x_m, y_m, z_m)` use the calibrated tool point `p_tcp + R_tcp @ tool_offset` when `position_point == "tool_point"`, otherwise raw `p_tcp`.
      - For segment length $L = \text{end} - \text{start} \ge 2$, let $t_i = \text{progress}_i \cdot (L - 1)$, $f_0 = \lfloor t_i \rfloor$, $f_1 = \min(f_0 + 1, L - 1)$, $\alpha = t_i - f_0$. Position `(x_m, y_m, z_m)` is linearly interpolated between `f0` and `f1`; `yaw_deg` uses shortest-arc linear interpolation in `(-180, 180]`. When $L = 1$, all $K$ points repeat frame `0`.

### Exact Subtask-Arm Metric Definitions (Viewer Alignment)

When `xense-lerobot-viewer` recomputes metrics for any user-selected subset of episodes, it must match `lerobot-check distribution --episodes <subset>` using these exact formulas:

1. **Start / End Occupied XY Cells (`occupied_xy_cells`)**:
   - Count of distinct `(floor(x_m / xy_bin_m), floor(y_m / xy_bin_m))` pairs across the selected episodes' non-null `start_pose` (or `end_pose`). `0` if 0 non-null poses (including the last subtask where `end_pose` is `null`).
2. **Start / End Yaw Span (`yaw_span_deg`)**:
   - Circular span on $S^1$ over non-null poses: `0.0` if $M \le 1$.
   - For $M \ge 2$, wrap each `yaw_deg` into $[0, 360)$ via `((yaw % 360) + 360) % 360`, sort ascending to $\theta_0 \le \dots \le \theta_{M-1}$, compute the $M$ consecutive gaps $g_i = \theta_{i+1} - \theta_i$ ($0 \le i < M-1$) and $g_{M-1} = (\theta_0 + 360) - \theta_{M-1}$.
   - `yaw_span_deg = max(0.0, 360.0 - max(g_0, ..., g_{M-1}))`.
3. **Trajectory Dispersion (`trajectory_dispersion_cm`)**:
   - `null` if $M = 0$; `0.0` if $M = 1$.
   - For $M \ge 2$ episodes each with $K$ trajectory positions $P_{e,k} = (x_{e,k}, y_{e,k}, z_{e,k})$ in meters:
     - At each progress index $k \in \{0, \dots, K-1\}$, let $\bar{P}_k = \frac{1}{M} \sum_{e=0}^{M-1} P_{e,k}$.
     - Population 3D position std (`ddof=0`): $\sigma_k = \sqrt{\frac{1}{M} \sum_{e=0}^{M-1} \|P_{e,k} - \bar{P}_k\|_2^2}$.
     - `trajectory_dispersion_cm` $= \frac{100}{K} \sum_{k=0}^{K-1} \sigma_k$.

## `suggestions.json` (Schema Version 1)

Generated by `lerobot-check suggest`.

### Top-Level Fields

| Field | Type | Description |
| --- | --- | --- |
| `version` | `int` | Always `1`. |
| `provenance` | `object` | Source paths, `layer` (`"object"` or `"tool"`, the pose layer passed with `--layer`; absent in older files, which used `"tool"`), `region_source` (`"target_polygon"` or `"data_bbox_plus_5cm"`), `seed`, `count_per_object`, `test_per_tier`, `arrow_length_m` (`0.05`), collision note. |
| `objects` | `list[object]` | Per-object sampling geometry: `object`, `arm`, `z_plane_m` (object layer: `object_layer.plane_z_m`; tool layer: `median_z_m`), `yaw_symmetry_deg` (object layer: `object_layer.yaw_period_deg`; tool layer: the task spec symmetry), `polygon_base_xy_m` (`[[x, y], ...]`), `polygon_pixel` (`[[u, v], ...] | null`). |
| `omitted_objects` | `list[str]` | Objects with zero observed poses or no grid cells inside the target polygon. |
| `placements` | `list[object]` | Collection placements (`N` per object), empty cells first, then sparse, spread across yaw bins. |
| `test_points` | `list[object]` | Evaluation test points across three tiers (`"dense"`, `"edge"`, `"empty"`), `test_per_tier` per tier per object. |

### Placement & Test-Point Item Schema

Every element in `placements` and `test_points` has identical keys:

| Field | Type | Description |
| --- | --- | --- |
| `object` | `str` | Object name from task spec. |
| `arm` | `str` | Arm whose base frame holds `(x_m, y_m, z_m)`. |
| `index` | `int` | 1-based sequence number within `(object)` for placements, or within `(object, tier)` for test points. |
| `x_m`, `y_m`, `z_m` | `float` | Base-frame target coordinates in meters (`z_m` equals the object's `z_plane_m`). |
| `yaw_deg` | `float` | Suggested folded yaw angle in `[0, yaw_symmetry_deg)` degrees. |
| `ix`, `iy`, `yaw_bin` | `int` | Coverage grid cell indices containing this point. |
| `cell_count` | `int` | Observed count in `(ix, iy, yaw_bin)` for placements, or total XY cell count in `(ix, iy)` for test points. |
| `tier` | `str` | `"empty" | "sparse" | "dense"` for placements; `"dense" | "edge" | "empty"` for test points. |
| `pixel` | `[float, float] | null` | Projected `[u, v]` in head-camera pixels (`null` when uncalibrated). |
| `arrow_end_pixel` | `[float, float] | null` | Projected `[u, v]` of `(x_m + 0.05*cos(yaw), y_m + 0.05*sin(yaw), z_m)` (`null` when uncalibrated). |

### Target Polygon & Calibration Rules

- `targets/<org>__<name>.json`: `{"version": 1, "camera": "observation.images.head", "image_size": [640, 480], "polygon": [[u, v], ...]}`.
- When `head.json` calibration is present, `distribution.json` **must** also have been computed with calibration (`provenance.position_point == "tool_point"`) so object poses and `median_z_m` planes sit at the calibrated tool point rather than raw TCP; `suggest` refuses with an error if `distribution.json` has `position_point == "tcp"` while calibration is present.
- When a target polygon is provided (via `--targets` or the default `targets/` path), `head.json` calibration is required; `suggest` fails with an error rather than silently falling back if calibration is absent.
- When no target polygon exists, `suggest` emits a warning and uses each object's observed data bounding box expanded by 5 cm on each side (`region_source: "data_bbox_plus_5cm"`).

## Collection mask bundle (`masks/<org>__<name>@<revision>.json`, v1)

`mask-overlays` writes a separate JSON document without changing `suggestions.json`. The top-level keys are `version: 1`, `repo_id`, `revision`, `camera`, `image_size: [W, H]`, `calibration_sha256`, `suggestions_sha256` (hex digests of the source file bytes), `sources` (template provenance by object), and `targets`.

`placement` rows are identified by `(kind, object, index)` and omit `tier`: the placement tier in `suggestions.json` describes sampling priority, not a test category. `test_point` rows also include `tier` (`dense`, `edge`, or `empty`) in their identity. Both kinds retain `pixel` and `arrow_end_pixel` from the suggestion row. The display number is the bare index for placements and `D`, `E`, or `X` followed by the index for test points. `outline` is an implicitly closed exterior ring in native head image coordinates; it is `null` when unavailable. Exactly one of `outline` and a nonempty explanatory `reason` is present (the other is `null`).

`mask-template` writes a separate per-object input JSON with `anchor_layer` (`"object"` by default, or `"tool"` with `--layer tool`; templates without the field are tool-layer templates). With the object layer, the anchor is the source episode's `object_layer` pose: the source records `event: "head_mask"`, the pose frame, XY, `raw_yaw_deg` and `folded_yaw_deg`, and `z_plane_m` is `object_layer.plane_z_m`; the reference yaw is `folded_yaw_deg`. With the tool layer, the source records the annotated pose-anchor frame (grasp or release), the event tool-point XY and raw yaw, `z_plane_m` is `median_z_m`, and the reference yaw is `raw_yaw_deg`. Both record the RGB image frame separately from the anchor frame, along with the model revision and prompts. The exterior is back-projected to `z_plane_m + height_offset_m`, translated by the negative anchor XY and unrotated by the reference yaw to store `outline_xy_m` in local meters. At each target the reverse transform uses the target XY and a per-period yaw equivalent nearest the reference yaw, the same height offset, and the object's calibrated arm. The original arrow retains the suggested folded yaw. A `--reject` template supplies a reason instead of local geometry and still records `anchor_layer` and the layer's `z_plane_m`; with the object layer it fails when the object has no `object_layer`. `mask-overlays` and `collection-plan generate` refuse a template whose `anchor_layer` differs from the suggestions' or plan's layer.

## Calibration File Contracts (`calib/*.json`, Schema Version 1)

- `intrinsics.json`: `version`, `camera`, `device`, `image_size` (`[W, H]`), `fx`, `fy`, `cx`, `cy`, `distortion_model`, `distortion` (`[k1, k2, p1, p2, k3]`). Always read from file; never hard-coded.
- `frames.json`: `version`, `repo_id`, `revision`, `camera`, `image_size`, `frames: [{"id": "left-000", "arm": "left", "episode_index": int, "frame_index": int, "tcp": [x, y, z, r1..r6], "speed_mps": float}]`. Newly sampled frames are filtered to closed-gripper (`gripper <= 0.05` by default, configurable via `--max-gripper`) and slow-moving (`speed <= 0.03` m/s TCP central-difference speed within each episode by default, configurable via `--max-speed` or disabled with `--no-speed-filter`) frames so fingertip midpoints are sharp to click. Use `--append K` (optionally scoped with `--arms left[,right]`) to add frames while preserving all existing entries verbatim as FPS seeds.
- `points.json`: identical to `frames.json`, adding `"pixel": [u, v]` (midpoint of fingertips) or `"skipped": true`.
- `head.json`: `version`, `repo_id`, `revision`, `camera`, `image_size`, `intrinsics` (copied verbatim), `arms: {<arm>: {"T_cam_base": [[4x4]], "tool_offset": [ox, oy, oz], "n_points": int, "n_inliers": int, "rms_px": float, "inlier_rms_px": float | null, "loo_rms_px": float | null, "inlier_loo_rms_px": float | null, "outlier_threshold_px": float, "residuals": [{"id": str, "du": float, "dv": float, "outlier": bool}]}}`.
  - Forward model: `pixel = project(K, dist, T_cam_base @ (p_tcp + R_tcp @ tool_offset))`, where `R_tcp = rotation_6d_to_matrix(r1..r6)`.
  - Joint least squares uses two-stage robust loss (`soft_l1` warm start followed by redescending `cauchy` refinement, `f_scale = 3.0` px), initialized from `solvePnP` / `solvePnPRansac`.
  - Residuals: `du = u_pred - u_obs`, `dv = v_pred - v_obs`. Points with `hypot(du, dv) > max(3 * median_err, 15.0)` px are flagged `"outlier": true` without being dropped.
  - `rms_px = sqrt(mean(du^2 + dv^2))` over all points; `inlier_rms_px` over non-outlier points. `loo_rms_px` and `inlier_loo_rms_px` are computed by refitting independently on each leave-one-out fold (`N >= 6`).
